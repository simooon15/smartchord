# SmartChord · 智能吉他谱

交付一个完整、可直接双击打开的 HTML，所有谱数据、原谱、必要音色均内嵌。工作文件和 QA 留在 work/，不把半成品当最终交付。用户指定其他产品或交付格式时优先遵循用户指令。

## 先确认调与变调夹

从现有消息和原谱提取已知设置，只问缺少的信息，尽量一次问清：

- 原谱的指法调、原变调夹品位（图上没有时说明）。
- 要弹的**指法调**，例如 G 指法；目标**变调夹品位**，例如第 2 品。
- 想要的**实际发声调**（若已给前两项，计算后告知，无须再追问）。

例如：“想用什么指法调、夹第几品？如果只确定实际调，也可以告诉我。”若只给实际调，提出容易按的指法调/Capo 组合供选择。公式是指法根音 + Capo 半音 = 实际根音，保留大小调；G 指法 + Capo 2 = 实际 A 调。三个参数矛盾时必须澄清，不能暗自覆盖。升调段保持原曲相对转调关系，并逐段标出新的指法调和实际调。

默认标准六弦调弦。非标准调弦、特殊装饰奏法或更复杂的声部，需要先适配模板与校验器，不能套用标准调弦算法伪造准确结果。

## 原谱先于转调

使用 [原谱转录与数据契约](references/transcription.md) 阅读输入、记录每小节的原图位置并构造 `source.json`。PDF 用 `scripts/prepare_sources.py` 保留原文件并逐页渲染；截图保留原始顺序和哈希。检查所有页，而非只读 OCR 文本。

逐音记录弦/品、拍点/时值、和弦变化、扫弦方向与实际弦范围、连音/延音、休止、歌词和简谱。相同图形可复用，但每次出现必须对照原图；重复演奏与重复截图不同，要按反复、房子与歌词展开演奏顺序。不要生成常见伴奏型替代缺失转录。

×、方框 ×、箭头等依原谱图例和上下文解释。此次《仓颉》的普通 × 是当前和弦弦位音、方框 × 按拍弦处理，**不能推广为其他谱子的固定规则**。不可确定且影响音高/节奏的记号才向用户问，继续完成其余确定部分；不清楚就不要宣布完整准确。

## 转调、指法与 HTML

读取 [工具与运行方式](references/tools.md)。先运行编译和结构验证，再构建 HTML：

```sh
python3 <skill>/scripts/score_tools.py work/source.json work/score.json
python3 <skill>/scripts/validate_score.py work/score.json --raw work/source.json
python3 <skill>/scripts/build_html.py work/score.json work/candidate.html
```

编译器先保留每个音的实际音高，再考虑独立弦位、可按跨度与四指限制。默认不调整八度；只有无法实现时，说明冲突并让用户选择保留原八度但改用其他调/Capo，或允许显式八度调整。已有用户授权可直接沿用。允许后仍逐项列出调整，不能把改八度称为完全等音高转调。不要删减同时声部来让指法看上去简单。

每个和弦名称下方放相应的基础指法图，优先开放和弦、低把位与小横按，核对完整和弦组成音和指定低音。基础图与旋律换指要明确区分。扫弦显示跨弦箭头，不能画成一列 picking 数字；准确扫弦声部用编号关联具体指法表。同一份数据驱动显示、音频和打印。连音、滑音、击勾弦等需检查相邻音的物理弦位；自动按事件求解不能替代这项检查，必要时用核实后的 `targetNotes` 修正。

屏幕按可用窗口宽度和小节内容密度自动分行，窄屏通常一小节，宽屏容纳更多小节；不能仅把固定桌面谱行加水平滚动。短音使用弹性间距保持可读，点击定位与游标必须使用同一坐标映射。窗口变化保留播放、模式、位置与开关状态；A4 独立使用固定纸谱分行，不继承手机布局。

播放器提供默认关闭的“主旋律”开关。开启后用真实钢琴采样播放已核实的人声简谱，与吉他伴奏独立混音；此提示音不是人声演唱，也不替代真实吉他采样。旋律实际音高、八度、临时变音必须可追溯；延音合并（包括跨小节），休止不发声，中途进入延音恢复剩余时值。两模式、变速、定位、循环和开关变化均保持同步、清理旧声源。无原谱旋律时不编写旋律；数据不完整应阻止构建。

## 音色与离线

只内嵌本曲原谱/目标两模式用到的音高采样，不嵌入整套 SF2、工作线程依赖或远程资源。[音色工具](references/tools.md#audio) 说明如何从已授权的钢弦吉他音色生成缺少的音高，并校准。包内小缓存是本次已用的 34 个音高，不是完整音域；缺少时构建器会报错，不能静默换成合成正弦音或移调邻近采样。

钢琴主旋律默认使用 assets/piano-cache 的 Salamander Grand Piano V3（Alexander Holm，CC BY 3.0），只内嵌两模式需要的已校准根音采样与显式音高映射。缺音域用 prepare_piano.py 扩充，不能退回正弦振荡器。保留真实起音、自然衰减与短松键尾音；从延音中间进入时使用采样偏移，避免重新敲键。来源、改编说明、署名与许可全文内嵌。

保留音色来源与署名；吉他缓存源的元数据未声明许可证，不声称可公开再分发。若用户要公开发布，换用明确许可或用户自有录音音色。普通本地生成不额外引入发布审批流程。

## 验收与交付

按 [验收门槛](references/acceptance.md) 完成原谱核对、自动浏览器/音频检查、真实操作及打印视觉检查。`browser_qa.cjs` 使用实际播放器合成路径检查音频与相邻半音，不是另一套模拟逻辑。自动 PASS 不是人耳试听或人类逐音认可；若不能直接听，明确记录自动音频证据与主观试听的区别。

运行 `scripts/practice_qa.cjs candidate.html work/qa-practice`，检查 320/390/600/900/1440 宽度重排、无横向溢出、主旋律开关、实际旋律频率、两模式整曲混音和手机进入 A4 打印。

运行 `scripts/rhythm_qa.cjs` 并检查实际符梁：八分一层、十六分两层、三十二分三层，附点与混合节奏要正确；修改绘制时同步更新共享的 assets/rhythm.js，不能重复叠加事件横线与分组符梁。

A4 默认紧凑布局约每行 3 小节、每页 4 行；密集三十二分音符、长和弦名、多歌词行可减少该行小节数。以可读性和实际渲染为准，不强行套固定页数。运行 `print_qa.py`，查看每页缩略图和密集页原尺寸截图，检查和弦图/箭头编号/歌词是否碰撞、跨页或截断。

全部检查通过后才复制最终 HTML 到 outputs/，确认离线可用和文件哈希；仅交付这一份 HTML。QA/源 JSON 留在用户工作目录以便下一轮修改。用户指定本地 Drive 目录时直接用本地文件，云端同步状态需要另证，不能从本地哈希推断。

## 点击播放与电脑媒体键

普通点击谱面（音符、箭头、歌词、空白）从对应拍点立即连续播放；原谱与目标、宽屏与窄屏共用坐标映射，音符/箭头用精确事件拍点。点击所选范围外切到整首；Option/Alt＋点击保留单事件试听。进度条与 QA seek 的默认暂停定位行为保持，显式 seek(at,true) 才自动启动。

用 Media Session 注册 play/pause/stop、歌曲元信息和播放状态。实际混音只经一个输出：支持时接入 MediaStreamDestination → HTML audio，以便浏览器路由系统媒体键；不播放占位静音音轨，也不重复输出。媒体元素不可用时保持 Web Audio 输出并记录降级。页面收到 MediaPlayPause/MediaPlay/MediaPause 时处理；空格切换仅限非输入框、菜单、按钮、链接或可编辑区域，忽略重复 keydown。异步解码/媒体 play 等待期间以请求编号保证最后一次操作有效；暂停必须取消待启动请求、停止媒体元素并清除声源。

运行 transport_qa.cjs，验证真实点击、Alt 试听、空格/媒体键事件、Media Session 回调、真实 audio 流和状态、快速跳转/加载中暂停。自动回调不等于物理系统键验收，后者单独记录设备/浏览器与系统会话路由。A4 仍须实际渲染复核。
